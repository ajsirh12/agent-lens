# Requirements Extraction

자연어 기능 요청을 구조화된 요구사항 문서로 변환한다.

## 추출 프로세스

### Step 1: 요청 분해

사용자의 자연어 요청에서 다음을 분리한다:

1. **핵심 의도** — 사용자가 해결하려는 문제 (요청 문장 그대로가 아님)
2. **명시적 요구사항** — 사용자가 직접 언급한 것
3. **암묵적 요구사항** — 언급하지 않았지만 당연히 기대하는 것
4. **범위 외** — 이번 요청에 포함되지 않는 것

### Step 2: agentlens 컨텍스트 매핑

요구사항을 agentlens 도메인에 매핑한다:

| 요구사항 유형 | agentlens 매핑 |
|---|---|
| 데이터 표시 | Timeline DataTable 컬럼, 포맷팅 |
| 시각화 | Flowchart 노드/엣지, 레이아웃 |
| 인터랙션 | 키바인딩, 모달, 포커스 |
| 데이터 소스 | parser.py 이벤트 타입, JSONL 필드 |
| 필터/검색 | 새 UI 컴포넌트 또는 기존 패널 확장 |

### Step 3: 수용 기준(AC) 작성

AC는 반드시 검증 가능한 형태로 작성한다:

**나쁜 예:** "사용자가 이벤트를 필터링할 수 있다"
**좋은 예:** "Timeline에서 `f` 키를 누르면 필터 입력창이 표시되고, 'tool_use'를 입력하면 tool_use 타입 이벤트만 남는다"

AC 템플릿:
```
AC{N}: {동작}하면 {결과}가 {상태}이다
  - Given: {전제 조건}
  - When: {사용자 액션}
  - Then: {검증 가능한 결과}
```

### Step 4: 모호성 체크리스트

다음 항목을 순회하며 모호성을 식별한다:

- [ ] 범위: "모든"이 정말 전부인지, 일부인지
- [ ] 트리거: 자동인지, 수동(키바인딩)인지
- [ ] 표시 위치: 기존 패널인지, 새 패널인지
- [ ] 데이터 소스: 기존 파싱 데이터로 충분한지, 새 필드가 필요한지
- [ ] 지속성: 세션 간 유지인지, 앱 종료 시 리셋인지
- [ ] 에지 케이스: 데이터 없을 때, 대량 데이터일 때

## 산출물 템플릿

```markdown
# Requirements: {기능 제목}

## 기능 요약
{1~2문장으로 핵심 의도}

## 요구사항

### 필수 (Must)
- REQ-1: {요구사항}
- REQ-2: {요구사항}

### 선택 (Nice-to-have)
- OPT-1: {요구사항}

## 수용 기준
- AC1: {Given/When/Then}
- AC2: {Given/When/Then}

## 모호성 (해소 필요)
- AMB-1: {질문} — 영향: {어떤 AC에 영향주는지}

## 범위 경계
- 이번에 하지 않는 것: {목록}

## 기존 기능 관계
- {기존 기능}과의 관계: {확장/독립/대체}
```
